MES 2 - Angular Intermedio + Buenas Practicas

Objetivo
Llevar Angular a un nivel mas profesional, trabajando con una SPA real, arquitectura separada por responsabilidades, manejo de estado reactivo, autenticacion, autorizacion y una UX mas cuidada.

Que use realmente en este proyecto

Frontend (Angular)
- Angular 20.
- Componentes standalone.
- Angular Router con rutas reales y proteccion de acceso.
- Guards para autorizacion por rol.
- Interceptors HTTP encadenados.
- Manejo de estado simple con BehaviorSubject.
- Reactive Forms con validaciones avanzadas y validacion cruzada.
- Angular Material para UI, dialogs, tablas, chips, forms, toolbar, progress bar y snackbars.
- Control de sesion con localStorage.
- Loader global para peticiones HTTP.

Backend (.NET)
- ASP.NET Core Web API en .NET 8.
- JWT para autenticacion.
- TokenService para generacion de tokens.
- ADO.NET para acceso a datos.
- Endpoint de login dedicado.
- Endpoint generico para entidades.
- BCrypt para hash de contraseñas.
- CORS y Swagger en desarrollo.

Base de datos (SQL Server)
- Tabla de usuarios.
- Tabla de roles.
- Stored procedures para listar, guardar y eliminar usuarios.
- Stored procedure de autenticacion.
- OPENJSON y FOR JSON PATH para interoperar con .NET.

Importante
Este proyecto avanzo bastante mas que el plan original del mes 2.

Proyecto 2
Sistema de Gestion de Usuarios

Objetivo del proyecto
Demostrar que sabes construir una SPA moderna en Angular con estructura profesional, estado reactivo, proteccion de rutas, manejo global de peticiones y una interfaz mas cercana a un entorno real de empresa.

Descripcion del proyecto
Sistema de Gestion de Usuarios es una SPA desarrollada en Angular que permite iniciar sesion, administrar usuarios, asignar roles y controlar si un usuario esta activo o no. El frontend esta organizado en capas core, features y shared. El backend esta hecho con ASP.NET Core Web API y usa SQL Server para persistencia. La autenticacion se resuelve con JWT y el guard de Angular protege las rutas administrativas.

Funcionalidades implementadas
- Login de usuario.
- Persistencia de sesion con token en localStorage.
- Toolbar con navegacion y logout.
- Ruta de inicio.
- Pantalla de gestion de usuarios.
- Listado de usuarios en tabla.
- Alta de usuarios.
- Edicion de usuarios.
- Eliminacion de usuarios con confirmacion previa.
- Visualizacion de rol mediante chip.
- Visualizacion de estado activo/inactivo mediante iconos.
- Carga de roles desde backend.
- Restriccion de acceso a gestion solo para admins.
- Loading global durante requests.
- Manejo global de errores con mensajes al usuario.

Que estudiaste de verdad en este proyecto

Angular intermedio/profesional
- Separacion de responsabilidades en core, features y shared.
- Uso de Router para una SPA con varias vistas.
- Guards para controlar acceso segun el rol del usuario.
- Interceptors para token, loading y errores.
- Manejo de estado con BehaviorSubject para usuario actual, usuarios y roles.
- Formularios reactivos con Validators y validador custom.
- Dialogos reutilizables para confirmacion y formularios.
- UI reactiva con async pipe.
- Ocultar o mostrar acciones segun permisos.

Buenas practicas aplicadas
- Store central para evitar logica duplicada en componentes.
- Interceptors para no repetir logica HTTP en cada pantalla.
- Guard para mover la autorizacion fuera de los componentes.
- Confirm dialog para acciones destructivas.
- Feedback visual al usuario con snackbars y progress bar.
- Carga de datos por observables y estado compartido.

Aclaracion tecnica importante
En el backend, cuando se guarda un usuario, la contraseña se procesa con BCrypt antes de enviar los datos a SQL. Eso muestra una mejora real respecto a un CRUD simple y suma mucho para explicar el proyecto.

Guards reales
Guard: adminGuard
Comportamiento
- Lee el usuario actual desde localStorage.
- Permite acceso a /usuarios solo si cdRol es 1.
- Si no es admin, redirige a /home.

Interceptors reales
- authInterceptor: agrega el token Bearer a cada request si existe.
- loadingInterceptor: prende y apaga un loader global durante las peticiones.
- errorInterceptor: captura errores HTTP, muestra mensajes con SnackBar y limpia sesion ante 401.

- wildcard a /login
